# 业务基线

本文件是当前产品意图的入口，工程约定见 [ARCHITECTURE](ARCHITECTURE.md)，开发规则见 [CONTRIBUTING](../CONTRIBUTING.md)。

## 用途与范围

IT团队将零散需求组织成项目与可交付工作，记录业务和开发双方的沟通、决策、验证、上线与实际使用结果。公开部署用于作品展示，固定合成演示身份，无需独立账号密码体系。

业务身份包括提出需求/验证结果的业务协作者、执行工作的开发者、维护项目的管理员和查看成果的管理人员。访问角色是super_admin/admin/editor/viewer及自定义角色，不能直接与职位画等号；开发者身份单独配置。

## 主要流程

1. 页面提交的新需求进入需求池；征集回执经判断后进入需求池或关联已有记录。历史兼容入口仍可直接建L3。
2. 需求评估、评审和补充形成决策；可拆多个分支，业务确认后才能按规则正式转换。一次来源可以形成多个独立L3。
3. 分类L1组织项目L2，L3是实际工作。阶段、日志、共享动态、评论、附件和待办支持执行协作。
4. 交付标准、业务验证和IT交付是不同状态；业务验证通过不会自动完成IT交付。
5. 符合确认/来源资格的交付安排开始使用后3天和30天回访。原物理字段day7表示3天，不能据字段名改规则。
6. 回访与运营问题进入对应交付轮次，后续有改善提案和知识记录。统计对同一requestId事实去重，独立请求/轮次分别统计。
7. PoC记录沉淀验证结果并可派生AI能力；绩效统计本人创建/被指派工作，定稿快照不能被后续计算覆盖。

## 保持的关键规则

- 一次转换的多分支创建共用事务；重复请求不创建第二批工作。
- 历史动态读取不写库，第一次评论/附件写入时按稳定ID物化；IT私有日志只向IT范围开放。
- 页面、按钮与直接访问遵循配置，API仍检查动作与资源范围。
- 同步撤回有后续人工编辑、日志、评论或附件时拒绝撤回。
- 通用知识库保持现有示例页范围；真实运营知识在运营模块保存。
- 删除/恢复/永久清理遵循层级、期限与权限，不把软删除当所有关联均可丢弃。
- GET不初始化业务记录或外发通知。旧接口、合法字段、状态/默认/空值和历史数据语义兼容保留。

## 当前展示边界

使用合成数据/Fake通知；浏览器会话失效后可重新建立。部分定向外链依赖原有token及接收者身份范围，公开管理员不能冒充所有接收者。真实钉钉身份/通讯录/通知为可选集成，不声称已真实投递。

本次公开仓库不扩展账号注册、密码找回、多租户或新的通知中心。内部业务能力和外部平台接入状态分别验收。
